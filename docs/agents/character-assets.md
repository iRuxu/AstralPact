# 工作台角色资产约定

本约定适用于在工作台操作和让 Codex 直接整理本地文件。现有《星契》角色继续沿用原路径。

```text
assets/characters/
└── 角色名/
    ├── index.json
    ├── README.md
    ├── 2d-turnaround.png
    ├── 3d-turnaround.png
    ├── model.glb
    ├── portraits/
    ├── skin/
    │   ├── 节庆装-2D.png
    │   └── 节庆装-3D.png
    ├── voice/
    │   ├── index.wav
    │   └── 生气.wav
    └── archive/
        └── 2026-11-23-v001/
            ├── index.json
            └── 3d-turnaround.png
```

初始化角色时建立 `index.json`、`README.md`、`voice/`、`portraits/`、`skin/` 和 `archive/`。图片、模型和音频可以各自缺省。直接新建空角色目录也会显示待补主图卡片。角色目录名即显示名，通过工作台改名时同步修改目录和 `name`，遇到重名返回错误。工作台通过 Vite 的文件监听响应外部新增、改动、删除和改名。外部手动改目录名时也应更新 `name`。

## 特写与皮肤

- 常规表情、角度、配饰特写放进 `portraits/`。可按需要再分组。工作台兼容读取旧项目的 `特写/`。
- 皮肤图片直接平铺在 `skin/`，用文件名区分造型、视角及 2D 或 3D 版本，例如 `红领带.png`、`地球顶-2D.png` 和 `地球顶-3D.png`。工作台仍读取旧目录和旧 `skins` 登记中的现有图片。皮肤图片不参与角色主图选择。
- 「特写」和「皮肤」用缩略图切换下方大图，默认预览首张。两页跳过 `archive/`，展示 `index.json` 中 `assetPrompts` 已登记的生成词。

## 角色与阵营目录

- 角色可以直接放在 `assets/characters/<角色名>/`，也可以放在 `assets/characters/<阵营>/<角色名>/`。有既有阵营目录时，将新角色落到对应阵营。编辑既有角色时先核对实际目录，使用原位置。
- 《星契》已有的 `01-龙族王室/` 这类带编号前缀的目录可直接识别为阵营。新建无编号阵营（例如 `龙族/`）时，在阵营目录内放一个内容为 `{}` 的 `group.json`。阵营名自动加入其角色卡片的可筛选标签，编号前缀会省略。
- 角色的明确入口是其目录根部的 `index.json`。独立角色目录、阵营下的直接角色目录可以暂时为空。狼队和狐狸父子已登记为分组，成员可凭各自的 `README.md` 或 `index.json` 识别。更深的层级沿用根目录 `AGENTS.md` 的资产嵌套规则。候选素材和历史文件按角色资产管理。

## Codex 直接落盘

1. 先从 `assets/characters/` 找到角色的实际目录，核对现行素材、`index.json`、`README.md` 和当前归档习惯。默认三视图使用 `2d-turnaround.<扩展名>` 和 `3d-turnaround.<扩展名>`。重命名时保留原扩展名，同步更新素材索引与现行引用。角色音色与台词统一存入 `voice/`。
2. 将用户确认采用的文件存到角色对应位置，更新 `index.json` 中的素材路径、生成词和需要变更的字段。默认音色使用 `voice/index.<扩展名>`，保留原音频格式。其他音色样本和角色台词使用描述性文件名，来源说明可随文件保存在同一目录。长设定更新 `README.md`。
3. 替换现行内容前，按下方规则归档旧文件和旧生成词。工作台上传会自动执行本地写入和归档。Codex 直接写文件时按同一规则一并维护归档和 `history`。

```json
{
  "name": "角色名",
  "tags": ["女性", "龙族"],
  "note": "",
  "image2d": "2d-turnaround.png",
  "image3d": "3d-turnaround.png",
  "model3d": "model.glb",
  "mainImage": "image3d",
  "voice": "voice/index.wav",
  "prompts": {
    "image3d": "生成这张图时实际使用的完整提示词"
  },
  "history": [
    {
      "version": "2026-11-23-v001",
      "changes": ["image3d"],
      "archivedAt": "2026-11-23T08:00:00+08:00"
    }
  ]
}
```

- `tags` 是文本数组，用于自定义标签。角色从目录继承分组标签；在概览删除继承标签并保存后，将该角色隐藏的分组标签记入 `hiddenGroupTags`。界面多选标签时取交集。概览的用户备注写入 `note`，角色故事和长设定写入 `README.md`。
- `image2d`、`image3d`、`model3d`、`voice` 是固定素材字段，值为相对角色目录的路径。图片支持 PNG、JPEG、WebP、AVIF。模型字段保留单文件 GLB 格式，工作台的模型入口暂缓开放。主音色按 `voice/index.<音频扩展名>` 识别，`voice/` 中其他音频也可浏览和试听。
- `mainImage` 指向 `image2d` 或 `image3d`。未设置或所指图片暂缺时，优先展示 3D 图，其次展示 2D 原画。没有图片时显示占位。
- `prompts` 按素材字段保存当前实际生成词。提示词未知时留空。使用新生成词替换现有图时，应在同一次修订中记录旧素材和旧生成词。
- `assetPrompts` 以角色目录内的相对文件路径为键，保存特写、皮肤、其他造型等独立文件的实际生成词。重命名或移动文件时同步更新键。工作台的默认素材生成词栏读取 `prompts`。

## 修订与迁移

- 归档用 `YYYY-MM-DD-vNNN`，例如 `2026-11-23-v001`。日期取归档日，版本号在每个角色下持续递增，同一天也递增。一次修订涉及多项内容时共用一个归档目录。工作台新建归档时在角色索引的 `history` 中保存 `archivedAt`，历史页按北京时间显示。旧归档优先使用目录名中的日期，无日期时显示目录创建时间。
- 替换现行图、音色或模型，或修订已有生成词时，将旧版 `index.json` 和本次被替换的文件保存到该归档。特写和皮肤的旧图也放在版本目录根部，对应生成词保留在归档索引的 `assetPrompts` 中。改写已有故事时将旧 `README.md` 保存到版本目录。当前 `index.json` 的 `history` 追加 `version`、`changes` 和 ISO 8601 格式的 `archivedAt`。首次补充缺失素材直接写入当前目录。
- 《星契》原有分组目录、`原画三视图.png`、`3D三视图.png`、`2d.*`、`3d.*`、`音色参考/`、历史归档目录可继续读取。旧分组名称会显示为标签，旧音色参考可以试听，设置了主音色后才点亮主音色标识。旧目录中独立存放的生成记录继续保留，逐步整理到各自归档版本。
- 已有角色的重命名会移动整个角色目录。其他文件里手写的跨目录 Markdown 链接需要同步检查。

## 《星契》既有角色的目录与制作记录

既有《星契》角色原有路径为 `assets/characters/<分组>/<角色目录>/`，现行素材与既有归档的布局如下：

```text
<角色目录>/
├── 2d-turnaround.png
├── 3d-turnaround.png
├── archive/                  # 历史图片、被替换稿，按版本或修订原因分子目录
│   └── 生成记录/             # 本角色历次生成词、生成记录与修改说明
├── voice/                    # 默认音色、参考样本、角色台词与来源说明
├── portraits/                     # 独立近景，可按视角、表情、服装变体命名
└── README.md                 # 角色背景、职责、当前版本、素材入口与生成记录链接
```

1. **当前素材与缺项。** 根目录的两张三视图是当前采用版本；原画为二维手绘设定，3D三视图为电影CG风格图片，不表示交付了3D模型。未制作的类别在README注明“暂缺／待制作”，可预留目录，不复制图片冒充另一种版本，不编造音色或生成词。
2. **文件命名。** 三视图统一为上述文件名；特写目录使用 `portraits/`，图片使用能说明角色、视角或表情的名称，已有镜号可保留。明确的服装变体平铺在 `skin/`，不把探索稿擅自替换为当前标准形象。新稿默认另存，用户明确修正当前图时先归档再替换。
3. **历史归档。** 被替换图放在该角色的 `archive/<版本或修订原因>/`，记录为何弃用、当前采用哪张。历史稿不作为默认生成参考，除非用户明确要求借用其中某部分。保留历史实际提示词，不为符合新设定而改写过去执行过的提示词；用当前版本说明标记旧要求已失效。
4. **生成与修改记录随资产归档。** 每个角色的历史生成词、实际生成记录、修订说明等放在该角色的 `archive/生成记录/` 下；历史图片仍可按修订原因放在同一 `archive/` 的子目录。场景与分镜同理，归入各自所属场景或场次目录的 `archive/生成记录/`。记录与素材就近维护，不再集中放入 `docs/生成记录/`。例如 `assets/characters/05-市场舆论/狐仙/archive/生成记录/大钻戒修订-生成记录.json`。跨角色的共享记录保留在所属场景归档，角色README按需链接；场景当前可用的即梦提示词Markdown仍可留在场次入口。
5. **记录内容与引用。** 保存完整实际提示词、实际附图顺序及用途、渠道、真实尺寸、是否后处理、生成结果、验收与已知问题、当前采用状态；模型、seed等未暴露信息不得猜测。角色或场景README链接到自身归档中的记录，说明当前采用版本与历史改动；无需额外创建全局记录中心。当前引用使用有效相对链接；历史输入路径保留时注明原位置和路径基准。
6. **README内容。** 写明姓名／别名、物种与年龄方向、职责／阵营、已确定背景、固定外形与配饰、当前各类文件入口、缺项及生成记录链接。区分用户已认可内容与新设计提案，不将未定剧情、亲缘关系、明星类型等补成事实；用户新设定及时同步到 `docs/世界观与角色.md`、`docs/角色美术设定.md`。角色取名不自动触发素材目录改名，例如银翼仍使用 `银龙/`。
7. **整理前先核对实际文件。** 用户可能已移动、删除或改名；以现存目录为准，不从缓存自行恢复已删除素材，不因旧README仍有文件名就认定图片存在。移动或重命名后更新相关README、当前设定文档与生成记录入口，检查链接、图片实际尺寸与素材完整性。不要为了整齐重写历史生成事实。
8. **三视图与特写的参考分工。** 原画锁全身比例、物种、服装和附肢结构；最新认可特写锁面部身份、材质与光照。其他角色仅作风格参考，不串入其身份、角冠、服装和配饰。逐人检查三角度的头饰、手爪、附肢、尾部与可见下肢；新生成特写不自动等于已获用户认可。

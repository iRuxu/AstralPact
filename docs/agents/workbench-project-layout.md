# 工作台项目目录约定

《星契》通过 `@2kog/kacha` 使用工作台，已接入角色、场景、道具、音频和其他资产。新剧可使用咔嚓的初始化命令，无限画布仍在规划中。

| 路径 | 用途 |
| --- | --- |
| `AGENTS.md` | 本剧协作入口，记录目录约定、制作流程和本剧的差异。 |
| `docs/agents/SKILLS.md` | 项目制作技能索引，列出常用任务、对应流程文档和工具入口。 |
| `scripts/<剧集>/` | 剧本及同集的剧本资料。 |
| `assets/characters/<角色名>/` | [角色元数据、素材和版本约定](character-assets.md)，兼容《星契》原有分组目录。 |
| `assets/scenes/<场景>/` | [场景主图、机位、环境变化与归档](scene-assets.md)。 |
| `assets/props/<道具名>/` | [实体道具与配饰](prop-assets.md)。 |
| `assets/audio/<音频名>/` | 背景音乐、音效与环境底声。 |
| `assets/other/<资产名>/` | [字标、图形、特效及扩展图](../../assets/other/README.md)。 |
| `storyboard/<剧集>/<场次>/` | 关键帧、当前提示词及场次说明。 |
| `canvas/` | 画布文档，保存节点、连线、布局和项目文件引用。目录名暂定。 |
| `package.json` | `name` 和 `description` 用作工作台左上角的项目名称和描述。本剧在这里登记工作台依赖。 |
| `config/logo.{ext}` | 可选的工作台项目图标，格式见根目录 `AGENTS.md`。 |
| `config/global.json` | 工作台全局配置。`locale` 保存「其它设置」里选择的界面语言。 |
| `tmp/` | 本地临时文件。 |

## 启动工作台

在《星契》根目录执行 `npm ci` 安装锁定的依赖，再执行 `npx kacha`。已全局安装时，可直接运行 `kacha`。工作台默认地址为 `http://127.0.0.1:24074`。

剧本、素材和项目配置保存在本剧目录中，可随项目放入微云同步目录。OSS 使用各项目根目录中的 `.env`。工作台源码和视觉规范在咔嚓仓库维护。 [咔嚓源码](https://github.com/iRuxu/kacha)

右上角的「全局设置 → 基本信息」可修改项目名称、描述和 Logo。上传的图标以原扩展名保存到 `config/logo.{ext}`，并在 `package.json` 的 `kacha.logo` 记录当前使用的扩展名。因此更换格式时可以保留之前的图标文件。

## OSS 存储

在右上角「全局设置 → 存储设置」填写阿里云 OSS Endpoint、Bucket、路径、AccessKey ID 和 AccessKey Secret。保存会更新项目根目录的 `.env`。路径填 Bucket 内的目录前缀，保存为 `OSS_PREFIX`，留空表示 Bucket 根目录。再次打开时，凭据留空表示沿用已保存的值。

点击工作台右上角的云朵预览项目与 OSS 的差异，在弹窗中确认下载或同步。咔嚓读取当前工作目录，包括还未提交的文件，并按各级 `.gitignore` 筛选。`archive/` 中的历史资产随项目同步。Git 元数据、`.env`、依赖目录、符号链接和本机同步状态会跳过。

`config/oss-sync.json` 记录这份项目副本已应用的云端版本和文件指纹，可以随项目流转。`.kacha/oss-sync/` 保存本机分片检查点、冲突备份和任务状态。新电脑可先在目标目录配置 `.env`，再运行 `kacha clone .`，也可以在工作台点「下载项目」，「仅下载更新」用于接收同事的改动。已上传的相同内容可以跨电脑复用，本机未完成的上传可继续原分片。移除操作需要额外确认，历史版本仍可保留原文件对象。

已有旧版平铺备份时，须从一份完整的本地项目执行一次「迁移并发布」。详细流程见[咔嚓 OSS 项目协作设计](oss-collaboration.md)。

## 在星契中迭代咔嚓

- 制作星契时遇到通用工作台需求，先在本剧的 `node_modules/@2kog/kacha/` 修改并用星契的真实数据验证。调试用 `npx kacha`，直接运行 `kacha` 会使用终端 PATH 中的全局版本。
- 验证后，将通用改动同步到 [咔嚓源码仓库](https://github.com/iRuxu/kacha)，由咔嚓仓库提交和发包。发布后再更新星契的包依赖和锁文件。星契专属的设定和资产继续留在本剧目录。
- `node_modules` 中的改动是临时的。执行 `npm ci` 或升级依赖前，先把需要保留的改动同步到咔嚓源码。

## 初始化与项目差异

- 初始化可重复执行。它补齐缺失的资产目录和模板，保留已有文件。
- 各剧可直接调整内容、命名和制作流程。画布入口目录的配置方式待定。
- 通用技能随咔嚓 npm 包发布，按根目录 `AGENTS.md` 从已安装的 `@2kog/kacha/skills/` 读取。`docs/agents/SKILLS.md` 继续作为制作流程与工具索引。

## 画布读取与现有文件接入

- 文件内容按目录职责读取。画布文档引用项目根目录下的相对路径，支持中文路径，便于项目在不同团队成员的电脑间移动。节点可在同一项目内复用角色图、场景图或关键帧。
- 列出当前可用素材时跳过 `archive/` 和临时文件。场次或角色的 `README.md` 已标记当前入口时，以该入口为准。历史分镜中的版本目录按各场现有入口逐项纳入。
- 文件移走或改名后，画布保留原节点与连线，并提示具体的缺失路径，便于重新关联。换项目存放位置时，相对路径仍可使用。
- 《星契》的 `scripts/`、`assets/` 和 `storyboard/` 已具备这套一级结构。先按现有角色、场景和分镜入口接入，遇到具体不兼容再调整对应路径并更新引用。

## 资产分组

角色、场景、道具和其他资产共用根目录 `AGENTS.md` 的资产嵌套规则。任何层级的分组可用 `group.json` 声明，资产用自己的 `index.json` 登记。
